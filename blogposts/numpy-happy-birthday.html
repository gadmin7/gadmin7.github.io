A from-scratch tutorial

Play Happy Birthday with NumPy

Gauri Toshniwal · October 11, 2026

You don't need an instrument, a recording or an audio library to make music. A sound is a list of numbers, and NumPy is very good at lists of numbers. We'll start with a single beep and finish with a small band playing Happy Birthday. Every figure plays its sound, draws it, and shows the numbers behind it.

25 seconds, computed in your browser from the same math

This is where we're heading: a short band intro with a plucked guitar-like part, bass and drums, and then Happy Birthday played on bells. It takes about 200 lines of Python, and we'll write all of them together.

What you need. Python with two packages: NumPy for the math, and SciPy to save sound files and to filter noise for the drums. Install them with pip install numpy scipy. You don't need to know any music theory or signal processing. If you can read a for loop, you can follow along.

How to read the figures. Each one has a play button, a graph, and a numbers panel with the array's shape and some of its values. Move your pointer over a graph (or tap it on a phone) and the table jumps to the samples under your finger.

The idea for this post came from the Sound Waves page of the University of Minnesota's Math 1155 course, which explains how frequency, amplitude and adding waves relate to what we hear. Here we turn those three ideas into a song.

Step 1 · your first sound

Sound is a list of numbers

A speaker makes sound by pushing a cone in and out. Write down where the cone is 44,100 times a second and you have a list of numbers. That list is the sound, and a WAV file stores exactly that. So making music with NumPy comes down to one job: computing the right numbers.

The simplest list is a sine wave. Its frequency, the number of full wiggles per second, is the pitch you hear. Its amplitude, how tall the wiggles are, is how loud it is. Here is a complete program that makes one second of a beep and saves it:

import numpy as np
from scipy.io import wavfile

SR = 44100                                   # samples per second


def save(name, x):
    wavfile.write(name, SR, (x * 32767).astype(np.int16))


t = np.arange(SR) / SR                       # the time of every sample in one second
x = 0.3 * np.sin(2 * np.pi * 440 * t)        # 440 wiggles per second, at 30% volume
save('beep.wav', x)

Run it and open beep.wav. Three things happened. np.arange(SR) / SR made 44,100 time stamps from 0 to just under 1 second. np.sin turned every time stamp into a height between −1 and +1, and 0.3 turned the volume down. save scaled the numbers to whole numbers between −32,767 and 32,767, which is the format sound files use.

t and x are one-dimensional arrays with the same length, one entry per sample. One second of sound has shape (44100,). Below, the same numbers appear three ways: as a graph, as a strip of colors, and as a table.

Step 2 · hz()

Notes are numbers too

To play a tune we need the frequency of every note. Luckily there's a standard way to number notes, called MIDI. Middle C is 60, and each key on a piano, black or white, adds 1. The A above middle C is 69, and it's tuned to 440 Hz. One small function turns any note number into a frequency:

def hz(note):
    return 440 * 2 ** ((note - 69) / 12)

Each step up multiplies the frequency by the twelfth root of 2, about 1.0595. Twelve steps multiply it by exactly 2, which musicians call an octave. From now on we can write music as plain integers. A chord is just a list: [62, 66, 69] is D major.

Step 3 · your first tune

Happy Birthday in beeps

We already have enough to play a song. A melody is a list of notes, and each note needs two things: which note it is, and how long it lasts. We'll count length in beats, so the tune can be sped up or slowed down later.

HAPPY_BIRTHDAY = [                           # (note, how many beats it lasts)
    (69, .75), (69, .25), (71, 1), (69, 1), (74, 1), (73, 2),
    (69, .75), (69, .25), (71, 1), (69, 1), (76, 1), (74, 2),
    (69, .75), (69, .25), (81, 1), (78, 1), (74, 1), (73, 1), (71, 1),
    (79, .75), (79, .25), (78, 1), (74, 1), (76, 1), (74, 3)]


def beep(note, seconds):
    t = np.arange(int(seconds * SR)) / SR
    return 0.3 * np.sin(2 * np.pi * hz(note) * t)


beat = 60 / 96                               # seconds per beat at 96 beats a minute
song = np.concatenate([beep(note, beats * beat) for note, beats in HAPPY_BIRTHDAY])
save('happy_beeps.wav', song)

beep makes one note. The list comprehension makes 25 of them, each a different length. np.concatenate joins the arrays end to end into one long array. Run it and open happy_beeps.wav.

It's clearly Happy Birthday. It also sounds like a microwave. The notes are flat and lifeless, and there's a click between each pair. The rest of this tutorial fixes that, one idea at a time.

Step 4 · envelope()

Giving each note a shape

Why the clicks? A raw sine starts at full volume and stops dead. Your ear hears that sudden jump as a click. Real sounds swell up, then die away. We can describe that shape as its own list of numbers between 0 and 1, called an envelope:

def envelope(n, attack, decay):
    t = np.arange(n) / SR
    e = np.exp(-t / decay)                   # fade out smoothly
    k = int(attack * SR)
    if k:
        e[:k] *= np.linspace(0, 1, k)        # quick fade in over the first k samples
    return e

The first attack seconds ramp up in a straight line. After that, exp(-t / decay) fades smoothly: after decay seconds the note is at 37% of its peak, after twice that 14%. The envelope has the same shape as the wave, so NumPy can multiply them element by element: sample 0 times sample 0, sample 1 times sample 1, and so on.

Step 5 · pluck()

A plucked string is eight sine waves

The clicks are gone, but a sine wave still sounds like a test tone. Here's why. A real string vibrates at its main frequency and at 2×, 3×, 4× that frequency, all at once. These extra waves are called harmonics. Their mix is the reason a guitar and a flute sound different when they play the same note. So let's add eight of them:

def pluck(note, seconds, volume=0.5, bright=1.0):
    n = int(seconds * SR)
    t = np.arange(n) / SR
    x = np.zeros(n)
    for h in range(1, 9):                                # harmonics 1 to 8
        loudness = bright ** h / h ** 1.1                # higher ones are quieter
        fade = np.exp(-t * (2.5 + 1.6 * h))              # higher ones fade sooner
        x += loudness * np.sin(2 * np.pi * hz(note) * h * t) * fade
    return volume * x * envelope(n, 0.003, 10)

Two details make it sound like a string. Each harmonic is quieter than the one before. Each one also fades faster, so the note starts bright and turns mellow within a second, just as a real string does. bright tilts the mix: below 1 the top harmonics are muted, above 1 they're boosted.

The loop is secretly a matrix

Each pass of the for h loop makes one full-length array and adds it into x. Stack those eight arrays on top of each other instead and you get a matrix: one row per harmonic, one column per sample. Adding down each column gives exactly the same x. In NumPy that is X.sum(axis=0).

Reading the recipe back from the numbers

We can also run the process backwards. A Fourier transform takes a slice of samples and measures how much of each frequency is inside it. Doing that every few milliseconds gives a spectrogram: time runs left to right and frequency runs bottom to top. It's a good way to check that a sound contains what you meant to put in it.

Step 6 · bell()

A bell is overtones that don't line up

For the melody we want something that rings out over the band. Swap the whole-number multiples for 2.76 and 5.4 and the string turns into metal. Bars and bells bend in shapes whose overtones fall between the harmonics of a string. The wave never quite repeats, and the ear hears a bell.

def bell(note, seconds, volume=0.35):
    n = int(seconds * SR)
    t = np.arange(n) / SR
    f = hz(note)
    x = (np.sin(2 * np.pi * f * t)
         + 0.35 * np.sin(2 * np.pi * f * 2.76 * t) * np.exp(-t * 6)
         + 0.15 * np.sin(2 * np.pi * f * 5.4 * t) * np.exp(-t * 12))
    return volume * x * envelope(n, 0.002, 0.9)

The two odd overtones also die fastest. The strike sounds metallic for a moment, then settles into a pure ring, like a glockenspiel or a music box.

Step 7 · pad()

A soft chord that breathes

A pad is a soft, held chord that fills the background, like a string section. This one takes a list of notes and plays each of them three times: once in tune, and once nudged 0.08 of a note up and down.

def pad(notes, seconds, volume=0.12):
    n = int(seconds * SR)
    t = np.arange(n) / SR
    x = np.zeros(n)
    for note in notes:
        for detune in (-0.08, 0, 0.08):
            f = hz(note + detune)
            x += np.sin(2 * np.pi * f * t) + 0.3 * np.sin(2 * np.pi * f * 2 * t)
    swell = np.minimum(1, t / 0.6) * np.minimum(1, (seconds - t) / 0.5).clip(0)
    return volume * x * swell / len(notes)

Why play slightly out of tune on purpose? Two tones that close together drift in and out of step. When their peaks line up they add up, and when they're opposite they cancel. The volume pulses at the difference between the two frequencies. This is called beating, and it's one of the effects on the Sound Waves page. A slow wobble makes a held chord sound alive. swell fades the pad in over 0.6 s and out over 0.5 s.

Step 8 · bass() kick() snare() hat()

Bass and drums from math and static

Now the rhythm section. The bass is the simplest voice we'll write: a low sine plus a quieter copy one octave up, with a quick fade at the end so notes don't blur together.

def bass(note, seconds, volume=0.45):
    n = int(seconds * SR)
    t = np.arange(n) / SR
    f = hz(note)
    x = np.sin(2 * np.pi * f * t) + 0.25 * np.sin(2 * np.pi * f * 2 * t)
    stop = np.minimum(1, (seconds - t) / 0.03).clip(0)   # quick fade at the very end
    return volume * x * envelope(n, 0.005, 0.5) * stop

A kick drum is a sine wave whose pitch falls. Ours starts at 160 Hz and drops to 50 Hz within about a tenth of a second. When the frequency changes over time, sin(2π · f · t) no longer works. Instead np.cumsum adds up the pitch sample by sample to keep track of how far the wave has turned. A fast drop in pitch plus a fast fade is what we hear as a thump.

def kick(volume=0.9):
    n = int(0.35 * SR)
    t = np.arange(n) / SR
    pitch = 50 + 110 * np.exp(-t * 30)                   # 160 Hz falling to 50 Hz
    phase = 2 * np.pi * np.cumsum(pitch) / SR            # add up the pitch so far
    return volume * np.sin(phase) * np.exp(-t * 9)

Snares and hi-hats have no clear pitch, so sine waves are the wrong starting point. They start from random numbers: rng.standard_normal(n) is pure static. A filter from SciPy then keeps only part of it. The snare keeps the middle, 1.5 to 8 kHz, and adds a short 185 Hz tone for body. The hat keeps only what's above 7 kHz and is gone in a few hundredths of a second.

from scipy.signal import butter, lfilter

rng = np.random.default_rng(7)


def snare(volume=0.35):
    n = int(0.25 * SR)
    t = np.arange(n) / SR
    b, a = butter(2, [1500, 8000], 'band', fs=SR)        # keep 1.5 to 8 kHz
    hiss = lfilter(b, a, rng.standard_normal(n)) * np.exp(-t * 18)
    body = 0.5 * np.sin(2 * np.pi * 185 * t) * np.exp(-t * 25)
    return volume * (hiss + body)


def hat(volume=0.12):
    n = int(0.06 * SR)
    t = np.arange(n) / SR
    b, a = butter(2, 7000, 'high', fs=SR)                # keep only above 7 kHz
    return volume * lfilter(b, a, rng.standard_normal(n)) * np.exp(-t * 70)

Step 9 · reverb()

Putting the band in a room

Everything so far sounds dry, as if played in an empty field. In a real room you hear a sound directly, then again as it bounces off the walls. We can fake that by mixing in delayed, quieter copies. This recipe is from the early 1960s and is known as a Schroeder reverb.

def reverb(x, wet=0.25):
    echoes = np.zeros_like(x)
    for delay, keep in [(1557, .84), (1617, .83), (1491, .82), (1422, .81)]:
        a = np.zeros(delay + 1)
        a[0] = 1
        a[delay] = -keep                                 # y[i] = x[i] + keep * y[i - delay]
        echoes += lfilter([1], a, x)
    for delay, g in [(225, .5), (556, .5)]:              # smear the echoes together
        b = np.zeros(delay + 1)
        b[0] = -g
        b[delay] = 1
        a = np.zeros(delay + 1)
        a[0] = 1
        a[delay] = -g
        echoes = lfilter(b, a, echoes)
    return x + wet * echoes / 4

The first loop makes four echo machines. Each repeats its input every 1,422 to 1,617 samples (32 to 37 ms) and keeps about 82% of the volume each time round. The delays differ slightly on purpose, so the echoes don't stack up into a metallic ring. The second loop runs two "all-pass" filters that smear the echoes into a smooth tail. The last line mixes the echoes in under the original sound. lfilter is doing the repeating for us. The comment shows the rule it applies.

Step 10 · Track and the band

Mixing is just adding

In step 3 we joined notes end to end with np.concatenate. That won't work any more. Our new notes ring on after the next one starts, and several instruments play at once. We need a way to put any sound at any moment.

The answer is two long arrays of zeros, one for each speaker, and a method that adds a sound into a slice of them. When two sounds overlap, their numbers simply add. That is all mixing is.

class Track:
    def __init__(self, seconds):
        n = int(seconds * SR)
        self.left = np.zeros(n)
        self.right = np.zeros(n)

    def add(self, start, sound, pan=0.0):
        i = int(start * SR)                              # which sample to start at
        sound = sound[:len(self.left) - i]
        self.left[i:i + len(sound)] += sound * (1 - pan) ** 0.5
        self.right[i:i + len(sound)] += sound * (1 + pan) ** 0.5

pan moves a sound left (negative) or right (positive). The square roots keep the total loudness steady as it moves.

Now we can write a short intro for the band. It's driven by a small table of note numbers. CHORDS is a four-bar loop of D, A, B minor and G, one of the most-used chord loops in pop. Each entry is a bass note and the three notes of the chord.

CHORDS = [(50, [62, 66, 69]),                # D       (bass note, chord notes)
          (45, [61, 64, 69]),                # A
          (47, [62, 66, 71]),                # B minor
          (43, [62, 67, 71])]                # G


def backing(track, bars, bpm=112):
    beat = 60 / bpm
    for bar in range(bars):
        t0 = bar * 4 * beat                              # when this bar starts
        root, chord = CHORDS[bar % 4]
        up = [note + 12 for note in chord]               # the chord, one octave higher
        pattern = [up[0], up[1], up[2], up[1], up[0], chord[2], up[1], up[2]]
        for i, note in enumerate(pattern):
            track.add(t0 + i * beat / 2, pluck(note, beat * 1.5, 0.3 if i % 2 else 0.38), pan=-0.25)
        if bar >= 1:                                     # bass and drums join in bar 2
            for q in range(4):
                track.add(t0 + q * beat, bass(root - 12 if q != 2 else root - 5, beat * 0.9))
            for q in (0, 2):
                track.add(t0 + q * beat, kick())
            track.add(t0 + 2.5 * beat, kick(0.6))
            for q in (1, 3):
                track.add(t0 + q * beat, snare())
            for e in range(8):
                track.add(t0 + e * beat / 2, hat(0.12 if e % 2 else 0.08), pan=0.4)
    return bars * 4 * beat                               # the second where the backing ends

Read it one bar at a time. Every bar plays the chord's notes one after another on the pluck, eight notes per bar. From the second bar the bass and drums join: kick on beats 1 and 3, snare on 2 and 4, hats in between. We'll only ask for two bars, which is about four seconds, so you'll hear D and then A. Ask for more bars and the loop carries on through B minor and G.

Then Happy Birthday itself. It's the same list of notes as step 3, played on bells and placed on the track instead of joined end to end. Underneath, a bass note and a plucked chord land every three beats, because Happy Birthday is a waltz.

HB_CHORDS = [(50, [62, 66, 69]), (45, [61, 64, 69]), (45, [61, 64, 69]), (50, [62, 66, 69]),
             (50, [62, 66, 69]), (43, [62, 67, 71]), (50, [62, 66, 69]), (50, [62, 66, 69])]


def happy_birthday(track, start, bpm=96):
    beat = 60 / bpm
    t = start
    for note, beats in HAPPY_BIRTHDAY:                   # the tune, on bells
        track.add(t, bell(note, beats * beat + 0.6, 0.42), pan=0.1)
        t += beats * beat
    for k, (root, chord) in enumerate(HB_CHORDS):        # one chord every 3 beats
        t0 = start + k * 3 * beat
        track.add(t0, bass(root - 12, 3 * beat, 0.35))
        for j, note in enumerate(chord):
            track.add(t0 + j * 0.02, pluck(note - 12, 3 * beat, 0.22), pan=-0.3)

Step 11 · the finished song

Putting it together and saving

The last few lines call everything we've written. Two bars of the band, one held pad chord to make room, then Happy Birthday at second 6:

track = Track(30)
end = backing(track, bars=2)                             # a 4.3 second intro
track.add(end, pad([62, 66, 69], 4 * 60 / 112, 0.1))     # one held chord
happy_birthday(track, start=6)

x = np.stack([reverb(track.left, 0.3), reverb(track.right, 0.3)], axis=1)
x = x[:25 * SR]                                          # keep 25 seconds
x = np.tanh(1.3 * x / np.abs(x).max()) * 0.8             # round off the loudest peaks
fade = int(1.5 * SR)
x[-fade:] *= np.linspace(1, 0, fade)[:, None]            # fade out the last 1.5 seconds
save('happy_birthday.wav', x)

np.stack(..., axis=1) puts the left and right arrays side by side as the two columns of one matrix, which is the layout a stereo WAV file uses. The next line scales the whole song so its loudest moment is exactly 1 and passes it through tanh, which rounds off the peaks. Then the last 1.5 seconds fade to silence, and save writes the file.

            track.add(t0 + 2.5 * beat, kick(0.6))
            for q in (1, 3):
                track.add(t0 + q * beat, snare())
            for e in range(8):
                track.add(t0 + e * beat / 2, hat(0.12 if e % 2 else 0.08), pan=0.4)
    return bars * 4 * beat                               # the second where the backing ends


HB_CHORDS = [(50, [62, 66, 69]), (45, [61, 64, 69]), (45, [61, 64, 69]), (50, [62, 66, 69]),
             (50, [62, 66, 69]), (43, [62, 67, 71]), (50, [62, 66, 69]), (50, [62, 66, 69])]


def happy_birthday(track, start, bpm=96):
    beat = 60 / bpm
    t = start
    for note, beats in HAPPY_BIRTHDAY:                   # the tune, on bells
        track.add(t, bell(note, beats * beat + 0.6, 0.42), pan=0.1)
        t += beats * beat
    for k, (root, chord) in enumerate(HB_CHORDS):        # one chord every 3 beats
        t0 = start + k * 3 * beat
        track.add(t0, bass(root - 12, 3 * beat, 0.35))
        for j, note in enumerate(chord):
            track.add(t0 + j * 0.02, pluck(note - 12, 3 * beat, 0.22), pan=-0.3)


track = Track(30)
end = backing(track, bars=2)                             # a 4.3 second intro
track.add(end, pad([62, 66, 69], 4 * 60 / 112, 0.1))     # one held chord
happy_birthday(track, start=6)

x = np.stack([reverb(track.left, 0.3), reverb(track.right, 0.3)], axis=1)
x = x[:25 * SR]                                          # keep 25 seconds
x = np.tanh(1.3 * x / np.abs(x).max()) * 0.8             # round off the loudest peaks
fade = int(1.5 * SR)
x[-fade:] *= np.linspace(1, 0, fade)[:, None]            # fade out the last 1.5 seconds
save('happy_birthday.wav', x)

Make it yours

Now that you've built it, it's easy to change. Swap HAPPY_BIRTHDAY for another list of (note, beats) pairs to play a different tune. Ask for bars=8 for a longer intro (and move start later to make room), change CHORDS for a different mood, or raise bpm to speed the band up. Call pluck with bright=1.3 for a sharper attack, or change 2.76 in bell to hear how one number changes the metal.

Every sound here came from three ideas: frequency is pitch, amplitude is loudness, and adding waves is mixing.

The audio on this page is computed live in your browser by a JavaScript version of the same code, with the same formulas and numbers. The drum noise uses a different random generator, so individual drum hits differ slightly from what Python gives you. Inspired by the Sound Waves page from the University of Minnesota.
